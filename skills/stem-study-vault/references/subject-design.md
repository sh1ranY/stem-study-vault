# Design tasks for the subject

Use with [learning-diagnosis.md](learning-diagnosis.md). Share an evidence framework across courses, not the same question format or ability label.

## Connect source coverage to capability coverage

For the current unit, identify each important source obligation and the action the learner must perform: substitute, model, explain, distinguish, convert, justify or check. Link the objective to its direct prerequisites, teaching passage and independent attempt. This supplements the source map; it does not replace or reduce source coverage. A concept can be taught and still lack an opportunity to try its new operation.

Each task needs a stable ID and version, target objective, complete local inputs, source/adapted/authored identity, acceptable answers or reasoning criteria, likely alternative error explanations, optional hints and a new check. Declare whether inputs reset or continue. Distinguish a deliberately unseen check from a worked or repeated question.

Separate composite failures when needed: simpler arithmetic, clarified language or a direct prerequisite task can reveal whether the main concept is actually missing. Accept equivalent correct methods and inspect reasoning as well as final answers. Never make an exact wording match the sole rubric for an open explanation.

## Three domain patterns

| Domain | Distinct observations | Useful representations | Verification |
| --- | --- | --- | --- |
| Signals and quantitative engineering | Evaluate definitions; distinguish slope from height; construct a model and check endpoints | Piecewise expressions, graphs, sample values | Recompute values, inspect limits and a new waveform |
| Software requirements | Distinguish behavior, constraint and goal; preserve conditions; interpret quantifiers | Natural-language statement, criteria table, counterexample data | Accept reasoned variants; check logical implications and missing assumptions |
| Relational databases | Identify a row; distinguish composite uniqueness, valid reference and non-nullness | Business rule, sample rows, DDL and allowed operations | Execute in an isolated fixture if useful; name engine limits |

These are original patterns inspired by course work, not claims that a whole university module has been validated. Select a representative current unit; expand only with actual subject materials and checks.

For signals, state step endpoint conventions and include relevant axes. For requirements, distinguish supplied client decisions from proposed assumptions; verifiable conditions need not always be numeric. For databases, state business multiplicity and reset conditions, and do not transfer extra constraints from a different schema. Never run teaching mutations on an existing learner database as an incidental verification step.

## Choosing the next task

Increase one relevant demand where practical: remove a scaffold, change the representation, add a decision, or combine previously taught skills. Novel numbers alone do not establish transfer. A new context can still be near transfer; label it accordingly. Record prior related instruction separately from exposure to this exact question or answer.

Reserve a later comparable task for retention and record the actual interval if it is attempted. Do not claim that a particular interval, item count or pass threshold is scientifically established by this skill. Task quality and teaching effects require evaluation beyond link checks or generated files.
