# 数据库：唯一的是组合，不是每一列

**以下作答是模拟资料。** 初次尝试者正确允许重复姓名，却因“11 已经出现”而拒绝 `(11, AI)`。其余三种拒绝能说明重复组合、外键不存在和空值的区别。先让他比较初始数据中两个含 11 的行，他便改口说“重复的是一部分，不是整个组合”。这支持针对联合主键的补讲，不能据此推断 SQL 编写水平。

## 补讲片段

一条选课记录回答的是“哪位学生选择了哪门课”。学生编号只能识别人，不能单独识别一条选课记录，因为一个人可以选多门课；课程编号也一样。把两个值一起使用，才能在这项业务规则下识别一条记录。

因此，联合主键检查的是两行的整对值是否相同。已有 `(11, DB)` 并不妨碍加入 `(11, AI)`，因为它们描述不同的选课。若把 `student_id` 单独设为唯一，反而会禁止一个学生选两门课，改变原本的业务规则。若课程列单独唯一，则会禁止不同学生选择同一门课。

组合不重复仍不代表记录一定有效。`(99, AI)` 是一个新组合，但学生 99 不存在，因此违反外键。`(NULL, AI)` 无法明确是哪位学生，本包通过显式非空约束拒绝它。这三个检查各有目的，不能把所有拒绝都统称为“主键重复”。对应的声明为：

```sql
CREATE TABLE Enrollments (
  student_id INTEGER NOT NULL,
  code TEXT NOT NULL,
  PRIMARY KEY (student_id, code),
  FOREIGN KEY (student_id) REFERENCES Students(student_id),
  FOREIGN KEY (code) REFERENCES Courses(code)
);
```

先口头解释每一行约束保护的业务要求，再判断一个新组合。随后转到 [t1 的电子书场景](source.md)：不要用“实体书只能被一个人借走”的生活经验覆盖题目明确给出的业务规则。
